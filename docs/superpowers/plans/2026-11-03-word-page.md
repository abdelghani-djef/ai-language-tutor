# Word Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tapping a word anywhere in LinguaCards opens a full page about it: scenes (short conversations) with pictures and translations, meaning and recorded pronunciation from free dictionaries, more pictures, "Did you know?" from Wikipedia, and word partners, all fetched or shipped in the browser with no server.

**Architecture:** Pure source modules (`src/lib/word/*`) each fetch one free API and parse it with a tested pure function; a cache layer stores responses in the Cache API. Ready-made scenes and picture choices are static JSON under `public/scenes/`, generated ahead of time by AI and validated by a test. One `WordView` component renders the page; it is mounted by the `/word` route and by a full-screen overlay used from Study and Stories.

**Tech Stack:** Next.js 16 static export, React 19, TypeScript, Tailwind 4, shadcn/ui on Base UI, Vitest, Transformers.js translator (existing `useTranslator`).

**Spec:** `docs/superpowers/specs/2026-11-03-word-page-design.md`

## Global Constraints

- Browser only: no server, no API routes, no keys, nothing paid. Every source must be called directly from the browser.
- Static export with `trailingSlash: true`: the route is `/word/?w=…`, read with `useSearchParams` inside `<Suspense>`, like `src/app/deck/page.tsx`.
- Fetched word data never goes into `localStorage` (it holds user data, ~5 MB). Use the Cache API (`caches.open("linguacards-words")`), and fall back to plain `fetch` when `caches` is missing.
- Ready-made scenes are not in the JS bundle: fetched from `/scenes/<packId>.json` when a word page opens.
- All interface text in `src/messages/word.ts` via `defineMessages({en, fr, ar})`; vocabulary "list" and "word" (not deck/card), "ready-made list" (not pack).
- Right to left: logical classes only (`ms-/me-/ps-/pe-/start-/end-`); arrow keys and arrow buttons swap direction in RTL.
- Sections with nothing to show are not rendered. Every online section has its own loading and "couldn't load" state; the page itself never errors.
- No surprise downloads: if the translation model is not in the browser's cache, show English with a "Translate" button.
- Child safety: pictures for own words only from a matching Wikipedia article (never open search); Tatoeba sentences must pass `isCleanSentence`.
- Credits shown for every picture, sentence and recording, with author and licence when the source gives them.
- The owner commits and pushes. No task commits; each task ends with checks passing and stops.

## Review Focus

1. A word with spaces, apostrophes or a question mark ("thank you", "you’re welcome", "how are you?") must make valid URLs and lookups: strip end punctuation, normalise ’ to ', encode with `encodeURIComponent`. Test in Task 1 and Task 2.
2. A source that is down, slow or returns 404/502 (Free Dictionary often 502s) must leave that section in "couldn't load" or hidden, never blank the page. Test in Task 2 (`fetchJson` returns `null` on failure) and Task 3 (dictionary falls back to Wiktionary).
3. Wikipedia disambiguation pages and title mismatches ("fine", "name") must not show pictures or "Did you know?". Test in Task 3.
4. Arabic interface: the page is RTL, scene arrows and keys reverse, English text keeps `dir="ltr"`. Checked in Task 9 browser verification, tested for keys in Task 6.
5. Opening a word that is in no list and not ready-made (a word partner like "crumbs") still renders: header from the dictionary, Tatoeba sentences, no crash on missing translation. Test in Task 4 (`useWordData` with no card and no pack).

  export function parseMediaList(json: unknown, max = 6): Picture[];

  export function fetchDictionary(word: string, lang: string): Promise<DictionaryEntry | null>; // en: Free Dictionary, one retry, then Wiktionary; other langs: Wiktionary
  export function fetchPartners(word: string): Promise<string[]>;   // en only: rel_jjb=<w> rendered as "<adj> <w>", then rel_trg; dedupe; [] for other langs
  export function fetchSentences(word: string, lang: string, to: string): Promise<Sentence[]>; // Tatoeba, filtered by isCleanSentence, max 6
  export function fetchArticle(word: string, lang: string, to: string): Promise<{ article: Article | null; pictures: Picture[] }>;

  type Tri = { en: string; fr: string; ar: string };
  export interface SceneLine { who: Tri; text: Tri }               // text.en uses the word
  export interface Scene { place: string; lines: SceneLine[] }      // place = key in places.json, 2–4 lines

### Task 8: Generate ready-made scenes and pictures (content)

**Files:**
- Create/replace: `public/scenes/places.json`, `public/scenes/<packId>.json` for all 20 packs in `STARTER_PACKS`, each with `complete: true`
- Create: `scripts/contact-sheet.mjs` → writes `docs/pictures.html` (a grid of every chosen picture with its word or place and credit)

- Consumes: the format and `validatePackScenes` from Task 4.

Run as a workflow (ultracode): 
1. One agent writes `places.json`: 60–100 everyday places (`bakery`, `kitchen`, `classroom`, `bus-stop`…), each `{emoji, label:{en,fr,ar}}` ("At the bakery" / "À la boulangerie" / "في المخبز").
2. Per pack (20 agents): write 4 scenes per word using only listed places, 2–4 lines, simple vocabulary at the level of that pack and earlier packs (same rule as `src/data/starter-stories.ts`), natural French and Modern Standard Arabic translations, `who` labels translated.
3. Per pack, a checker agent: reads the pack file as a native editor of English, French and Arabic; fixes unnatural English, wrong translations, scenes where the word is used in a different sense than the pack's translation, and anything unsuitable for children; runs `npx vitest run src/lib/__tests__/word-scenes.test.ts` until it passes.
4. Pictures: per pack, an agent searches Wikimedia Commons (`commons.wikimedia.org/w/api.php?action=query&generator=search&gsrnamespace=6&gsrsearch=<word>&prop=imageinfo&iiprop=url|extmetadata&iiurlwidth=640&format=json`) for each picture-able word (skip function words, greetings, numbers above ten, abstract words), downloads 2–3 candidate thumbnails to the scratchpad, **looks at them** (Read tool on the image), and keeps one to three that plainly show the word, are suitable for children and have a CC0 / CC BY / CC BY-SA / public domain licence; stores `{thumb, page, author, licence}` in that word's `pictures`. One more agent does the same for every place in `places.json` (`picture`).
5. Run `node scripts/contact-sheet.mjs`.
